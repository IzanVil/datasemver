How it decides

The strongest change sets the version

Every difference is matched against a rule, and every rule carries a severity. The highest one found becomes the bump; the others still reach the changelog.

Severity lives in your rules file, with strict and lenient profiles beside the defaults. A change no rule covers is reported as unclassified and never raises the bump.

What it measures

Distributions, not just schemas

A column can be rebuilt around its mean without moving it. These changes break everyone downstream, and a comparison of schemas and averages reports them as nothing.

The spread grows fortyfold, the mean stays put

Measured with a Kolmogorov–Smirnov statistic over a quantile grid the profile stores, so the old file does not have to be there.

distribution_shift major

Both labels are still there, in other proportions

The category set is unchanged, so a check of distinct values sees nothing. Measured with the Population Stability Index.

psi_greater_than: 0.25 major

The same thousand days, six years later

A date column is compared on when it actually sits, so an export that slid forward, or now covers half the period, is a change instead of a silence.

distribution_shift major

A third of the rows rewritten, the profile barely moved

With --key, rows are matched instead of summarised. Values drawn the same way keep the shape of the column, and are a different dataset to anyone joining against it.

rows_modified minor

Each shift is weighed against what the sample can support: it has to clear the critical value for those sample sizes as well as your threshold. On a handful of rows nothing is reported, because there is nothing to report.

Engines

Profile a file larger than memory

The default engine loads a dataframe. --engine duckdb aggregates over the file instead, and duckdb-sketch also estimates the quantile grid, the one number that costs a full pass.

Wall time and peak resident memory of the whole process, profiling the same file with each engine.

The same report, to float rounding

duckdb answers what pandas answers. The sketch is named, never automatic: on eight rows it answers 1 where the exact path answers 1.35, just where a result is easiest to check by hand.

A ceiling you set

Set DATASEMVER_DUCKDB_MEMORY_LIMIT and what does not fit spills to disk instead of failing.

# half the memory, same answers
datasemver diff old.parquet new.parquet \
  --engine duckdb

Profiles

A comparison reads a profile: the columns, their types, their null ratios, a quantile grid and the counts per category. It is small enough to commit beside the dataset, and then the previous version never has to be fetched, or exist.

A Parquet footer can stand in for a scan with --schema-only; any comparison against that profile says no distribution was checked.

# write it once, next to the data
datasemver profile v3.parquet

# compare against it later, the file long gone
datasemver diff v3.profile.json v4.parquet

Ways in

Seven ways in, one report

  • Command line

    datasemver diff old.csv new.csv

    Built on typer and rich. Add --json when a script reads the answer instead of a person.

  • Python library

    from datasemver import analyze

    Two paths, or two profiles already in memory when the data came from a warehouse query.

  • Web dashboard

    pip install "datasemver[web]"

    A local tool with no authentication and no rate limiting: keep it on the loopback interface.

  • GitHub Action

    uses: IzanVil/datasemver@v0.8.2

    Posts the bump on each pull request, rewriting one comment. Past your threshold it refuses the merge, after saying why.

  • DVC

    datasemver dvc --rev HEAD~1

    Compares the datasets DVC reports as changed between two revisions, from the version recorded beside each.

  • Database tables

    postgresql://…/db#customers

    SQLite needs no driver; PostgreSQL and MySQL use the sql extra.

  • Standalone binary

    linux · windows · macos

    One executable per platform with its own Python, databases and workbooks included.

Install

Into a release script in five lines

Python 3.10 to 3.14, typed, and no network access at runtime. Releases are published from CI through Trusted Publishing with signed provenance, so no long-lived token exists.

sql
PostgreSQL and MySQL tables
excel
Workbooks, a sheet at a time
duckdb
The two engines for large files
web
The dashboard
View it on PyPI
release.sh 
# read the bump from a script
BUMP=$(datasemver diff old.csv new.csv --json | jq -r '.bump')

# prepend the changelog entry to the file you keep
datasemver diff old.csv new.csv --output CHANGELOG.md \
  --current-version "$(cat VERSION)"

# refuse a breaking change
datasemver diff old.csv new.csv --fail-on major

# which rows changed, not only whether the shape did
datasemver diff old.csv new.csv --key id

# record the version it computed
datasemver diff old.csv new.csv --write-version \
  --current-version 1.4.2

Questions

Before the first run

Do I need the previous file?
No. A stored profile counts as a dataset on either side, so the version before can be a 3 KB file committed beside the data.
Can I decide what counts as major?
Yes. Severity lives in a YAML rules file you pass with --rules; strict and lenient profiles ship beside the defaults.
What happens to a change no rule covers?
It is reported as unclassified, so you see it, and it never raises the bump.
Does my data leave the machine?
No. DataSemver makes no network requests at runtime, and the dashboard is meant to stay on the loopback interface.
How large a file can it read?
Larger than memory, with --engine duckdb. Set a memory limit and what does not fit spills to disk.
And on a machine without Python?
Every release carries one executable per platform with its own Python, databases and workbooks included.
