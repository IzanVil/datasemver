Semantic versioning for datasets

Your data changed.
What should the version be?

DataSemver compares two versions of a dataset, classifies every difference it finds, and answers with the bump they deserve — plus the changelog entry that explains it.

datasemver diff clientes_v1.csv clientes_v2.csv --current-version 1.4.2

What changed

major Column legacy_code was removed
major Column phone changed type from int64 to string
minor Row count grew from 40 to 48 (+20.00%)
minor Column country was added
patch Column email nulls dropped from 20.0% to 0.0%
patch Column monthly_spend mean moved 3.19%

The bump is the strongest severity found. Two changes break what consumers already depend on, so the rest cannot soften it.

Code has SemVer. Data doesn't.

A dropped column, a phone number that turned into a string, a distribution that quietly shifted. All of them break the people downstream, and all of them usually ship as "updated the dataset". DataSemver makes that impact explicit and reviewable, so a dataset release can be discussed the way a library release is.

How it decides

Every difference is matched against a rule, and each rule carries a severity. The bump is the strongest severity found across all of them. Anything no rule covers is reported as unclassified and never inflates the result.

Major — existing queries can break

Something consumers already depend on is gone or has changed meaning.

  • column_removed
  • type_changed_incompatible
  • column_renamed
  • distribution_shift

Minor — new information, contracts hold

There is more than there was, and nothing that was there has moved.

  • column_added
  • row_count_increased
  • new_category_added
  • cardinality_changed

Patch — same meaning, better data

The dataset says what it said before, with fewer gaps or less noise.

  • nulls_fixed
  • minor_stat_change
  • type_changed_compatible

Severity is a property of your rules file, not of the change. The bundled defaults are one opinion; strict and lenient profiles ship alongside, and the full catalogue lists every rule, metric and threshold.

See it

The command prints the bump, the column comparison and the classified changes, then the changelog entry. Nothing is written unless you ask with --output.

Four ways in

All four return the same report.

Command line

datasemver diff old.csv new.csv, and --json when a script needs to read the answer.

pip install datasemver

Python library

analyze() for two paths, analyze_schemas() for dataframes you already have in memory.

from datasemver import analyze

Web dashboard

Upload two files or pick two versions from a directory. A local tool with no authentication — keep it on loopback.

pip install "datasemver[web]"

GitHub Action

Analyses the datasets a pull request touches and posts the suggested bump as a comment, rewritten on each push.

scripts/run_datasemver_on_pr.py 
# the bump, ready for a release script
BUMP=$(datasemver diff old.csv new.csv --json | jq -r '.bump')

# the changelog entry, prepended to a file you keep
datasemver diff old.csv new.csv --current-version "$(cat VERSION)" --output CHANGELOG.md

Get it

Python 3.10 or newer. The package ships typed, and releases are published from CI through Trusted Publishing with signed provenance — no long-lived token exists.

$ pip install datasemver
